# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

GastosDiarios is a personal finance manager (dashboard, accounts, movements, transfers, budgets, reports, savings goals, debts, net worth, calendar, recurring payments, categories, insights, settings). It is a **client-only web app with no build step**: the data logic is in ES modules, and the UI is driven by **Alpine.js** with **Tailwind CSS** styling, **Lucide** icons and **Chart.js** charts, all loaded from CDNs. There is no backend. All data lives in the browser's `localStorage`. The app is a **PWA** (`manifest.webmanifest` + `sw.js` cache-first): after the first visit the resources (including the Tailwind/Lucide/Chart.js/Alpine CDNs) are cached and the app renders **offline**; only the very first load requires internet.

## Commands

```bash
npm start        # Serve on http://localhost:3000 via `npx serve`
```

There is no build, lint, or test tooling. A local server is required (not just opening `index.html`) because `src/app.js` is an ES module, which browsers block over the `file://` protocol (the service worker also only registers over `http(s)`). For a quick logic sanity check run `node smoke.mjs` (79 ESM assertions against `storage.js`/`stats.js`/`finance.js`/`export.js`) — the pure modules do not need a browser; `app.js`/`index.html` need browser testing.

## Architecture

The UI is a single Alpine component; the data logic stays in framework-agnostic ES modules.

- **`index.html`** — the whole view. Loads Tailwind (Play CDN, configured inline with `darkMode: 'class'` and an `accent` color mapped to `rgb(var(--accent) / <alpha-value>)`), Inter (Google Fonts), Lucide, Chart.js and Alpine. Markup is Tailwind utility classes + Alpine directives (`x-data="app"`, `x-for`, `x-text`, `@click`, …). Layout: collapsible left sidebar, sticky topbar, and 12 views toggled by `view` (`inicio`, `cuentas`, `movimientos`, `presupuestos`, `reportes`, `metas`, `deudas`, `patrimonio`, `calendario`, `recurrentes`, `categorias`, `config`). Includes the FAB (`#fab`), 10 modals, the global-search drawer and the toast (`#toast`). Reusable class combos live in the `<style type="text/tailwindcss">` `@layer components` block (`.card`, `.field`, `.form-label`, `.btn-ghost`, `.btn-icon`, `.nav-link`, `.chip`, …). Report printing is handled by `@media print` rules in `styles/main.css` (`.no-print` hides the actions/filters). PWA metas in `<head>` reference `manifest.webmanifest` and the theme color.
- **`src/app.js`** — registers the Alpine `app` component on the `alpine:init` event. Holds all reactive state (`state`, `view`/`viewYear`/`viewMonth` (0-based), sidebar/notif/profile/fab toggles, `search` (debounced)/`globalQuery`/`txFilter`/`txAccount`/`txCategory`/`dateFrom`/`dateTo`/`sortBy`/`sortDir`/`txLimit`/`txExpanded`, report filters, `form`/`entryType`/`editingId`, account/category/recurring/goal/debt modal forms, `confirm*`, `reassign*`, `selectedDay`, `accent`, `mode`, PIN/lock state (`locked`/`pinInput`/`pinError`/`pinDraft`/`revealAmounts`), `toast`, …), exposes derived data as **getters** (`kpis`, `monthExpenses`, `totalIncome`, `totalBalance`, `savings`, `budgetRows`, `allTx`/`filteredTx`/`visibleTx`/`hiddenTxCount`, `breakdown`, `alerts`/`alertCount`, `notifications`, `insights`, `goalList`/`debtList`, `patrimonio`/`patrimonioSeries`/`projection`, `recurringList`, `calendarCells`, `reportByCategory`, `reportsSeries`, `evolutionSeries`, `savingsSeries`, …) and actions (`openTxModal`, `submitTx`, `removeTx`, `duplicateTx`, `submitAccount`, `adjustBalance`, `submitCategory`, `deleteCategory` (+reassign flow), `submitRecurring`, `registerRecurring`, `setBudget`, `setCatBudget`, `setCurrency`/`setLocale`/`setDateFormat`, goal/debt CRUD (`openGoalModal`/`submitGoal`/`adjustGoal`/`openGoalContribution`/`submitGoalContribution`, `openDebtModal`/`submitDebt`/`openDebtPayment`/`submitDebtPayment`/`markDebtPaid`), receipts (`onReceiptFile`/`removeReceipt`/`receiptsFor`), PIN/lock (`setPin`/`lockNow`/`unlockApp`/`toggleAmountsHidden`), `expandTx`/`collapseTx`, `doExport`/`doExportCSV`/`doExportReportsCSV`/`doExportMonthly`/`doImport`/`loadDemo`/`resetData`, `goTo`, `changeMonth`, `doPrint`, `renderCharts`, …). Mutations call `this._save()` (save + analysis-cache invalidation) and re-render charts/icons in `$nextTick`. Delegates all data work to `storage.js`/`stats.js`/`finance.js`.
- **`src/storage.js`** — persistence and pure data helpers. Owns the v3 `state` shape (`{ version, budget, income, expenses, transfers, recurring, accounts, categories, catBudgets, settings, goals, debts, activity, widgets, receipts, privacy }`), `localStorage` load/save (key `gastosdiarios-v1`, wrapped in try/catch — `saveState` returns a boolean), JSON import via `importState(text)` (validates + sanitizes; throws on files without data), sanitizers for every record type (`sanitizeExpense`, `sanitizeIncome`, `sanitizeTransfer`, `sanitizeRecurring`, `sanitizeCategory`, `normalizeAccount`, `sanitizeGoal`, `sanitizeDebt` — all **drop** records with invalid amounts), the seeds (`ACCOUNT_TYPES`, `ACCOUNT_ICONS`, `FREQUENCIES`, `ACCOUNT_DEFAULTS`, `CAT_BUDGET_DEFAULTS`), `defaultState()` and `demoState(y, m)`, and the factories (`createExpense`, `createIncome`, `createTransfer`, `createRecurring`, `createAccount`, `createCategory`, `createGoal`, `createDebt`). Compatibility helpers `filterByMonth`/`sumExpenses`/`groupByCategory` remain; prefer `stats.js`. Schema migration lives in `src/migrations.js` (v1→v2→v3; the v2→v3 path only seeds new collections if the key is missing, so re-importing legacy JSON never clobbers data).
- **`src/stats.js`** — pure business logic: `sum`, `filterMonth`, `groupSum(records, keyFn)` (returns a `Map`), `pctChange` (returns `{ pct, up }` or `null`), `topExpenses`, `dayStats`, `nextRecurringDate`, `upcomingRecurring`, and `insights(state, y, m, { fmt, catLabel })` which returns a list of `{ icon, text, tone }` computed from the real data (no external AI).
- **`src/finance.js`** — net-worth math: `totalAssets` (accounts + investments + contributions), `totalDebt`, `netWorth` (assets − debt), `netWorthSeries`, `projectSavings` (yearly savings projection used by the reports view).
- **`src/validation.js`** — data-health: `analyzeState(state)` (per-account anomaly checks) and `safeFixState(state)` (moves broken data to `state.issues` instead of deleting it). `app.js` caches the analysis in `_analysisCache` and invalidates on every `_save()`/`undo()`.
- **`src/backup.js`** — automatic local backups: time-sliced envelopes in `localStorage` (restore from Config), independent of `export.js`.
- **`src/migrations.js`** — state-shape migration chain `v1 → v2 → v3` (remaps old category ids `comida→alimentacion`, `ocio→entretenimiento`, `hogar→vivienda`; seeds v3 collections only when absent).
- **`src/export.js`** — `downloadJSON(state)`, `csvCell`, `toCSV(rows)` (BOM is added in `downloadCSV`, not in `toCSV`), `downloadCSV(rows, name)`, `downloadText(text, name)`.
- **`src/categories.js`** — the editable list of categories (id, label, Lucide `icon`, `emoji`, `color`). `getCategory()` falls back to the last category (`otros`) for unknown ids.
- **`theme.config.js`** — user-facing customization: brand name/tagline, logo (Lucide `logoIcon` or a `logoImage` URL/photo), `locale`/`currency`/`dateFormat`, `defaultBudget`, accent color + presets, default theme mode.
- **`manifest.webmanifest`** / **`sw.js`** / **`icons/icon.svg`** — PWA. `sw.js` is cache-first with background refresh for same-origin files and the Tailwind/Lucide/Chart.js/Alpine/font CDNs; navigations fall back to `./index.html`. Bump its `VERSION` whenever you change app resources so old caches refresh. The manifest points to `icon.svg` (any purpose, maskable) and the theme color.

### Reactivity & conventions

- Alpine tracks state automatically — mutate `this.state`, call `this._save()`, and the getters/DOM update on their own. There is no manual `render()`. `_save()` persists via `storage.saveState` and invalidates `_analysisCache` (validation) so health alerts stay fresh.
- **Pagination/performance**: `filteredTx` is the fully filtered+ordered list; the table renders `visibleTx` (first `txLimit` rows unless `txExpanded`), with `hiddenTxCount` driving "Mostrar N más". Search inputs use Alpine's `x-model.debounce` (global 200ms, movimientos 250ms) to avoid re-rendering on every keystroke.
- **Icons**: Lucide replaces `<i data-lucide="…">` placeholders with SVGs via `lucide.createIcons()`. Alpine re-creates those placeholders inside `x-for`, so any action that changes a list calls `this.$nextTick(refreshIcons)` to re-render icons. Add that call to new actions that mutate rendered lists.
- **Theming**: the accent color is a CSS variable (`--accent`, space-separated RGB set by `applyAccent`); light/dark is the `.dark` class on `<html>` toggled by `applyMode`. Both are `$watch`ed and persisted (`gd-mode` in `localStorage`). Charts read the mode in `renderCharts()` to pick text/grid colors.
- **Charts**: Chart.js instances are owned by the component (`this._charts = {}` keyed by canvas id) and rebuilt in `renderCharts()` — call it inside `$nextTick` after any action that changes data or the month, or when the accent/mode changes. Guard with `if (!window.Chart) return`. The doughnut center-text uses a plugin passed as an extra-options array (`_chart(id, type, data, options, extraPlugins)`).
- **XSS**: Alpine's `x-text` auto-escapes, so user input needs no manual escaping. Do not switch list rendering back to `innerHTML`/`x-html` with user data.
- Record shapes: an `expense` is `{ id, amount, category, description, note, date, createdAt, account }`; an `income` drops `category`; a `transfer` is `{ id, amount, from, to, description, note, date, createdAt }`; a recurring payment is `{ id, name, amount, category, account, frequency, nextDate, active, createdAt }`; an `account` is `{ id, name, type, icon, color, balance, currency, status, createdAt }`; a category is `{ id, label, icon, emoji, color }`; a goal is `{ id, name, amount, saved, deadline, note, createdAt }`; a debt is `{ id, name, total, paid, monthlyPayment, nextDue, note, status, createdAt }` (status `activa`/`pagada`); a receipt (in `state.receipts`) is `{ id, recordId, dataUrl, name, size, createdAt }`. `id` uses `crypto.randomUUID()`; `date` is a `YYYY-MM-DD` string; amounts are rounded to 2 decimals. `viewMonth` is **0-based**; `dateStr(y, m, d)` expects a 0-based month.
- **Balances**: expenses subtract from `account.balance`, incomes add to it; transfers move between `from`/`to`; editing or removing a record must revert the previous balance effect first (`_applyBalance`/`_revertRecord`).
- **Recurring payments never auto-charge**: when `nextDate` arrives the item shows as pending and the user chooses "Registrar gasto" (creates an expense and advances `nextDate` via `stats.nextRecurringDate`) or "Saltar" (advances without recording).
- Dates are parsed as `new Date(date + 'T12:00:00')` to avoid timezone/off-by-one-day issues — reuse this idiom.
- Currency/locale/date format come from `theme.config.js` defaults and can be overridden in `state.settings`; `Intl.NumberFormat` formats currency. UI strings are in Spanish.
- `viewYear`/`viewMonth` track the displayed month independently of today; records are flat arrays filtered by `stats.filterMonth()` at read time.
- State changes that touch account balances or add/remove records must call `saveState(this.state)` and re-render charts.
- **PIN/lock**: when `state.privacy.pinEnabled` is true and the app loads, or after `state.privacy.autoLockMinutes` of inactivity (tracked via `gd-last-activity`), the app shows a lock overlay (`locked`). `unlockApp` checks `pinInput` against `state.privacy.pin`. `revealAmounts` hides amounts: `fmt()`/`compactFmt()` return `'••••'`. `setPin(true)` requires `pinDraft` (4–6 digits) and stores it; disabling clears the stored PIN.
- **Receipts**: attached during tx modal editing; stored compressed as `dataUrl` JPEG in `state.receipts` with a generated `recordId`; cleaned up when the record is deleted (`removeTx`).
